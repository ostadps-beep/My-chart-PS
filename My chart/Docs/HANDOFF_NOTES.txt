HOW WE WORK WITH PS (workflow that worked)
- The cloud sandbox has NO dotnet. You write code and tests, hand-check expected numbers against the spec formulas, then PS runs on Windows:
      cd "...\My chart"
      git fetch ; git checkout <branch> ; dotnet test
  PS pastes the output. "Passed! Failed: 0" => change the log line from PENDING to PASS and merge.
  The warning "No test is available in ...Generator.Tests.dll" is harmless (that project has no tests yet).
- Write the node on a branch named claude/t<node>-<name>, log it as PENDING, push, ask PS to run dotnet test.
  After PS's PASS: set the log line to PASS (include the test count), commit, `git checkout main`, `git merge --ff-only <branch>`, push main.
  Only verified code goes to main.
- Build settings: net8.0, Nullable enabled, ImplicitUsings, TreatWarningsAsErrors=true. One compiler warning breaks the build,
  so avoid unused variables, unused usings are fine, nullable mistakes are not.
- Tests: xUnit. Beware Assert.Equal(double, double?, int) does not compile: use .GetValueOrDefault() for nullable doubles.
  Tests of a calculator go in MyChart.Tests/<Area>/ (Analysis, Scale, Market, Smoke). Use the golden-vector fixture view
  (N 100, plotLeft 0, plotWidth 800, BarSpacing 8, RightOffset 5, range 1.09400..1.10600, plotHeight 500) where the spec uses it.
- Calculators are pure static classes in MyChart.Core (Analysis/, Scale/, Candles/). No UI, no IO, time passed in (no DateTime.Now).
  Display time zone is a nullable TimeZoneInfo parameter (UTC when null) because Core has no display-zone setting yet.

REPO ACCESS NOTES (cloud session)
- Push works through the session's git proxy after add_repo with access "push". Clone is shallow: `git fetch --depth 50 origin <branch>` to connect histories.
- Branch DELETE does not work from the sandbox (proxy refuses). PS must delete stale branches in GitHub (Branches page) or run
  `git push origin --delete <branch>`. Stale now: claude-access-test, claude/t3-01-crosshair, claude/t3-02-hud (+ later branches once merged).
- The stop hook may warn "unpushed commits / no remote branch" even after a successful push. It is a false alarm caused by a missing
  tracking ref in the shallow clone. Check `git ls-remote --heads origin <branch>` equals `git rev-parse HEAD`, then run
  `git fetch --depth 50 origin +<branch>:refs/remotes/origin/<branch>` and
  `git config branch.<branch>.remote origin ; git config branch.<branch>.merge refs/heads/<branch>`.
